# Imprescindible o deseable

- **Por sección:** Requisitos / Must have → imprescindible. Se valorará / Plus → deseable. Funciones / Ofrecemos → contexto
- **Por lenguaje:** «sólido» pesa más que «valorable»
- **Por años:** negociables (Galadrim pide 0)
- **Por el rol real:** lee las funciones, no el título
- Candidatura si cubres **≥ 60–70 %** de lo imprescindible *con evidencia*

- Viñeta = verbo + qué + cómo + resultado
- Prueba del copiar y pegar

# Con asistente de IA vs sin él

**Permitido** (p. ej. Provectus): te evalúan por **descomponer, especificar, verificar y explicar**.
Test primero → cambios pequeños → leer el diff → entrada vacía y grande.

**Prohibido** (p. ej. ICF): fluidez y razonamiento. Practica **sin** asistente y **habla en voz alta**.

Alterna las dos preparaciones.

---

# Live coding en 5 pasos

1. Reformula y pregunta (vacío, duplicados, tamaño)
2. Ejemplo a mano
3. Idea y coste **antes** de escribir
4. Código claro
5. Prueba: ejemplo, vacío, límite, entrada grande

# Diseño de sistemas de ML: 9 apartados

Objetivo → métrica de negocio → métrica técnica → datos y etiqueta → línea base → validación sin fugas → despliegue → monitorización → riesgos

*Con LLM: evaluación, guardarraíles, coste/latencia, seguridad.*

# STAR

**S**ituación · **T**area · **A**cción (60 %, en primera persona) · **R**esultado

5 historias sirven para casi todo: error, desacuerdo, aprendizaje rápido, explicar a no técnicos, proyecto orgulloso.

*Tu proyecto en 2 minutos:* gancho → decisión → mi decisión técnica → resultado + limitación → cierre.

# Inglés técnico B2

- Leer ofertas y documentación a diario
- Pedir aclaraciones: *«Could you clarify…?»*
- Pensar en voz alta: *«My first idea is… the trade-off is…»*
- Aceptar errores: *«Good catch, let me fix it.»*
- README bilingüe = práctica + evidencia
